Every name in `lauren_di.__all__`, with the signature it is called with and the
docstring that documents it. The page is generated by `scripts/build_reference.py`

## Container and scopes

### DIContainer

```text
DIContainer(
    *,
    overrides: OverridePlan | None = None,
    strict_request_scope: bool = False,
    value_tokens: Iterable[Any] = (),
    field_predicate: Callable[[str, Any], bool] | None = None,
)
```

Compiled DI container; immutable after `compile`.

`overrides` is applied while rows are registered. `strict_request_scope`
turns the lax request-scope fallback into an error. `value_tokens` nominates
tokens that are supplied from a scope rather than by a provider.
`field_predicate` returns `False` for class-body annotations your own layer
owns, so they are left alone.

Registration: `register`, `register_class`, `register_instance`,
`register_value`, `register_factory`, `register_alias`,
`register_custom`. Resolution: `compile`, `resolve`, `scope`.
Lifecycle: `startup`, `shutdown`. Introspection: `get_provider`,
`has_provider`, `all_providers`, `registered_providers`,
`applied_overrides`, `singletons`, `set_singleton`,
`mark_singleton_initialized`, `instance_index`, `adopt_lifecycle`,
`explain`. Visibility: `set_visible`, `grant_visible`, `visible_in`.

<!-- docs-contract: run -->
```python
from lauren_di import DIContainer

container = DIContainer()
```

### ResolutionScope

```text
ResolutionScope(
    container: DIContainer,
    *,
    values: Mapping[Any, Any] | None = None,
    origin: str = "scope",
)
```

One open resolution scope, owning the cache of request-scoped instances.

The scope is the single owner of that cache: nothing else may tear it down,
and closing it twice is a no-op rather than a double teardown. Values the
host supplies (a request object, a job context) are visible to every
resolution made through this scope.

Resolving inside a closed scope raises `LifecycleViolationError`
instead of silently constructing an instance whose teardown will never run.

<!-- docs-contract: run -->
```python
import asyncio

from lauren_di import DIContainer


async def main() -> None:
    container = DIContainer()
    async with container.scope() as scope:
        assert scope.closed is False
    assert scope.closed is True


asyncio.run(main())
```

### Scope

DI scope values, ordered from narrowest to widest lifetime.

The numeric order is load-bearing: the compiler rejects an edge whose
consumer scope value is **greater** than its dependency's, because
that consumer would outlive the instance it received.

>>> Scope.TRANSIENT < Scope.REQUEST < Scope.SINGLETON
True
>>> Scope.SINGLETON > Scope.REQUEST   # singleton -> request: rejected
True

`label` returns the stable lowercase name (`"singleton"`,
`"request"`, `"transient"`) that messages and logs use, instead of
the `IntEnum.__str__` formatting, which differs across Python
versions.

<!-- docs-contract: run -->
```python
from lauren_di import Scope

assert list(Scope) == [Scope.TRANSIENT, Scope.REQUEST, Scope.SINGLETON]
assert Scope.SINGLETON.label == "singleton"
```

## Declarations

### injectable

```text
injectable(
    *args: Any,
    scope: Scope = Scope.SINGLETON,
    provides: list[type] | tuple[type, ...] | None = None,
    multi: bool = False,
) -> Callable[[_T], _T]
```

Mark a class or a function as a DI provider.

**Class form** — instances are produced by the class itself:

    @injectable()
    class UserRepo:
        db: Database                      # class-body field injection
        def __init__(self, cfg: Settings): ...

**Function form** — the decorated function is the factory and its
return value is the dependency:

    @injectable(scope=Scope.SINGLETON)
    def make_pool(settings: Settings) -> Pool:
        return Pool(settings.dsn)

`provides` binds extra tokens to the same provider (typically
runtime-checkable protocols), and `multi=True` lets several providers
share one token so consumers can depend on `list[T]`.

The decorator must be called: `@injectable()`.  The bare form
`@injectable` is rejected because Python would pass the decorated
object as a positional configuration argument, silently binding it to
nothing.

<!-- docs-contract: run -->
```python
from lauren_di import Scope, injectable


@injectable(scope=Scope.REQUEST)
class Session:
    pass
```

### injectable_meta

```text
injectable_meta(target: Any) -> InjectableMeta | None
```

Return the `InjectableMeta` attached to `target`, if any.

Reading a marker that was inherited from a base class raises
`~lauren_di.MetadataInheritanceError` instead of silently
registering the subclass with the base's scope and bindings.  This is
the same lookup `DIContainer.register` performs, exposed so tools
(containers, compilers, test helpers) can ask the same question.

<!-- docs-contract: run -->
```python
from lauren_di import InjectableMeta, Scope, injectable, injectable_meta


@injectable(scope=Scope.REQUEST, provides=[object])
class Row:
    pass


meta = injectable_meta(Row)
assert isinstance(meta, InjectableMeta)
assert meta.scope is Scope.REQUEST
assert injectable_meta(object) is None
```

### post_construct

```text
post_construct(fn: F) -> F
```

Mark a method to run after the instance is constructed.

Hooks run base class first, in definition order within a class.  For
singletons they run during `DIContainer.startup`; for request and
transient providers they run as part of the resolution that created the
instance.

<!-- docs-contract: run -->
```python
from lauren_di import injectable, post_construct


@injectable()
class Ready:
    @post_construct
    def warm_up(self) -> None:
        self.warm = True
```

### pre_destruct

```text
pre_destruct(fn: F) -> F
```

Mark a method to run during teardown.

Hooks run subclass first, in definition order within a class.  A
failing hook is recorded as a `~lauren_di.DestructError` and
teardown continues with the next instance.

<!-- docs-contract: run -->
```python
from lauren_di import injectable, pre_destruct


@injectable()
class Pool:
    @pre_destruct
    async def drain(self) -> None:
        self.closed = True
```

### Depends

Spelling-only alias for a dependency annotation.

`Depends[T]` evaluates to `T` itself, so no marker object and no
`Annotated` wrapper reaches the container.  The spelling exists for
readers coming from FastAPI and for symmetry with `Inject`; the
runtime token is always the bare type.

<!-- docs-contract: run -->
```python
from lauren_di import Depends


class Repo:
    pass


assert Depends[Repo] is Repo
```

### Inject

```text
Inject(token: Any) -> _InjectMarker
```

Override the resolution token for a parameter or class field.

By default `lauren_di` resolves a parameter by its type annotation —
`def __init__(self, repo: UserRepo)` looks up the `UserRepo`
provider. When the provider is registered against a non-class
token (a string or a `Token`), the type hint cannot itself
*be* the token — Python wouldn't accept a string in that position.
`Inject` is the escape hatch:

    @injectable()
    class CatsRepository:
        def __init__(
            self,
            connection: Annotated[Connection, Inject("CONNECTION")],
        ) -> None:
            self.connection = connection

The annotation type is still used by static checkers (mypy /
pyright will still verify `connection.execute(...)` against the
`Connection` interface), but the runtime resolution uses
`"CONNECTION"` as the lookup key.

Class fields work the same way:

    @injectable()
    class CatsRepository:
        connection: Annotated[Connection, Inject("CONNECTION")]

For convenience inside `inject=[...]` factory lists you may also
pass a bare token (string, `Token`, class) directly without
wrapping it in `Inject` — the wrapper is only needed when
you're writing a Python annotation.

<!-- docs-contract: run -->
```python
from typing import Annotated

from lauren_di import Inject, Token, injectable

DB_URL = Token("db_url")


@injectable()
class Client:
    def __init__(self, url: Annotated[str, Inject(DB_URL)]) -> None:
        self.url = url
```

### OptionalDep

```text
OptionalDep(token: Any)
```

Mark a member of an `injects=[...]` list as optional.

When the matching provider is missing at resolution time, `lauren_di`
passes `None` to the factory's positional argument instead of
raising `MissingProviderError`. NestJS exposes the same
capability via `{ token, optional: true }`; `lauren_di` keeps the
affordance type-safe with a small wrapper class so the inject
list reads top-to-bottom.

Example:

    use_factory(
        provide="CONNECTION",
        factory=lambda opts, optional_logger=None: ...,
        injects=[Options, OptionalDep("LOGGER")],
    )

<!-- docs-contract: run -->
```python
from lauren_di import OptionalDep

optional = OptionalDep("LOGGER")
assert optional.token == "LOGGER"
```

### InjectableMeta

```text
InjectableMeta(
    scope: Scope = Scope.SINGLETON,
    provides: tuple[type, ...] = (),
    multi: bool = False,
)
```

The immutable record `@injectable` writes onto the target.

`scope` is the lifetime the container builds the target in, `provides` the
extra lookup keys the same row answers to, and `multi` whether the row
accumulates so `list[T]` resolves to all of them.

<!-- docs-contract: run -->
```python
from lauren_di import InjectableMeta, Scope

meta = InjectableMeta(scope=Scope.TRANSIENT)
assert meta.scope is Scope.TRANSIENT
```

## Records and aliases

### Provider

```text
Provider(
    cls: type,
    scope: Scope,
    provides: tuple[type, ...],
    multi: bool,
    deps: tuple[tuple[str, Any], ...],
    post_construct: Callable[..., Any] | None = None,
    pre_destruct: Callable[..., Any] | None = None,
    owning_module: type | None = None,
    factory: Callable[..., Any] | None = None,
    field_deps: tuple[tuple[str, type], ...] = (),
    is_function_provider: bool = False,
    is_generator_provider: bool = False,
    provider_kind: str | None = None,
    alias_target: Any = None,
    optional_dep_names: frozenset[str] = frozenset(),
    positional_arg_names: tuple[str, ...] = (),
    post_construct_hooks: tuple[Callable[..., Any], ...] = (),
    pre_destruct_hooks: tuple[Callable[..., Any], ...] = (),
)
```

A compiled provider entry.

`cls` is the DI token the provider binds to. Despite the legacy
name, it is **not** required to be a class — string tokens and
`Token` instances live here too, registered through the
custom-provider helpers (`use_value`, `use_class`,
`use_factory`, `use_existing`). The annotation stays
typed as `type` for backward compatibility with the wide surface
of code that already imports `Provider`; callers that need to
reason about non-class tokens should use `provider_kind`.

`factory` is the callable actually invoked to produce an instance.
For classes it's the class itself (`Cls(**kwargs)`); for function
providers it's the decorated function. Keeping the split explicit
means the runtime never needs to ask "is this a class or a function?"
— it always calls `factory(**kwargs)`.

`deps` are constructor / function arguments to resolve via DI.
`field_deps` are class-body-annotated attributes resolved to plain
attributes set on the instance before `__init__` runs.

<!-- docs-contract: run -->
```python
from lauren_di import DIContainer, Provider, injectable


@injectable()
class Thing:
    pass


row = DIContainer().register(Thing)
assert isinstance(row, Provider)
assert row.scope.label == "singleton"
```

### CustomProvider

```text
CustomProvider(
    provide: Any,
    kind: str,
    value: Any = None,
    use_class: type | None = None,
    factory: Callable[..., Any] | None = None,
    inject: tuple[Any, ...] = (),
    existing: Any = None,
    scope: Scope = Scope.SINGLETON,
    multi: bool = False,
    name: str = "",
)
```

Immutable description of a non-standard provider registration.

Each variant of NestJS's "custom provider" recipe lowers into this
single record. Module compilation reads the `kind` discriminator
and dispatches to the right `DIContainer` registration
method. The structure is deliberately data-only so it survives
pickling, can be inspected from tests, and stays cheap to compare
across variations of the same module graph.

Attributes:
    provide: The DI token consumers will inject. Accepts any
        hashable value — a class, a string, or a `Token`.
    kind: One of `"value"`, `"class"`, `"factory"`,
        `"existing"`. Determines which payload field the
        container reads.
    value: Set when `kind == "value"` — the literal value to
        bind. Otherwise `None`.
    use_class: Set when `kind == "class"` — the class to
        instantiate when the token is resolved.
    factory: Set when `kind == "factory"` — a callable that
        produces the value. May be sync or async; `lauren_di` awaits
        coroutines automatically.
    inject: Tuple of tokens (in argument order) handed to the
        factory at instantiation time. Bare tokens may be
        classes, strings, or `Token` instances. To declare
        an *optional* dependency wrap the token in
        `OptionalDep`.
    existing: Set when `kind == "existing"` — the token whose
        already-resolved instance becomes the bound value.
    scope: Resolution scope (singleton / request / transient).
        Defaults to singleton, matching NestJS.
    multi: When `True`, the token participates in `lauren_di`'s
        multi-binding collection so consumers requesting
        `list[T]` see this provider alongside others.

<!-- docs-contract: run -->
```python
from lauren_di import CustomProvider

provider = CustomProvider(provide="answer", kind="value", value=42)
assert provider.kind == "value"
```

### Token

```text
Token(name: str, *, unique: bool = True)
```

A typed, branded identifier for non-class providers.

Plain strings already work as DI tokens, but `Token("DB_URL")`
gives three benefits over a bare string:

* **Identity vs equality.** Two `Token("X")` instances are
  *different* tokens by default, mirroring Python's `object`
  identity semantics. This is what NestJS's `Symbol`-based
  tokens give you and what most Python users expect when they
  "create a new token". (Pass `unique=False` to opt into
  string-style equality if you need to share the same name across
  processes / modules.)
* **Repr.** Errors mentioning `Token("DB_URL")` are far easier
  to grep for than errors mentioning a bare `"DB_URL"`, which
  could be any string anywhere in the codebase.
* **IDE friendliness.** A module-level `DB_URL = Token("DB_URL")`
  gives autocomplete and "find usages" without making the token's
  name part of the public API surface.

Tokens are hashable and compare by identity by default, so they
are safe to use as dict keys and set members. They are *not*
classes — passing a Token to a place that expects a Python type
(like a function annotation) is fine because `lauren_di`'s DI machinery
treats tokens as opaque hashable keys, not as type objects.

<!-- docs-contract: run -->
```python
from lauren_di import Token

assert Token("x") != Token("x")
assert Token("x", unique=False) == Token("x", unique=False)
```

## Custom-provider recipes

### use_value

```text
use_value(*, provide: Any, value: Any, multi: bool = False) -> CustomProvider
```

Bind `provide` to a pre-built value.

The value is treated as a singleton (no factory ever runs) and is
returned by the container on every `resolve()` call. Common
uses:

* inject a mock service in tests:

      use_value(provide=CatsService, value=mock_cats_service)

* register an externally-constructed object as a DI citizen:

      use_value(provide="REDIS", value=redis.from_url(...))

* expose a literal config dict to handlers:

      use_value(provide="CONFIG", value={"debug": True})

`multi=True` is supported for completeness — multiple
`use_value` registrations sharing a token can be assembled
into a list with `list[T]` consumers, although the more common
multi-binding pattern is on services rather than values.

<!-- docs-contract: run -->
```python
from lauren_di import DIContainer, use_value

container = DIContainer()
container.register_custom(use_value(provide="answer", value=42))
```

### use_class

```text
use_class(
    *,
    provide: Any,
    use: type,
    scope: Scope = Scope.SINGLETON,
    multi: bool = False,
) -> CustomProvider
```

Bind `provide` to a class — typically *different* from the token.

The classic example is environment-conditional configuration:

    configServiceProvider = use_class(
        provide=ConfigService,
        use=DevelopmentConfigService if dev else ProductionConfigService,
    )

The chosen class is constructed through the standard DI pipeline,
so its own `__init__` parameters resolve as if it had been
registered via `@injectable`. It does not need to itself carry
the `@injectable` decoration: `lauren_di` auto-marks classes used in
`use_class` with the matching scope so the factory machinery
works end-to-end.

<!-- docs-contract: run -->
```python
from lauren_di import DIContainer, Scope, use_class


class Greeter:
    pass


container = DIContainer()
container.register_custom(use_class(provide="greeter", use=Greeter, scope=Scope.TRANSIENT))
```

### use_factory

```text
use_factory(
    *,
    provide: Any,
    factory: Callable[..., Any],
    injects: Iterable[Any] = (),
    scope: Scope = Scope.SINGLETON,
    multi: bool = False,
) -> CustomProvider
```

Bind `provide` to the result of calling `factory`.

`injects` lists the tokens `lauren_di` resolves and passes *positionally*
to the factory in declaration order. This positional contract is
deliberately the only one supported — it keeps the call site small
and unambiguous, and matches NestJS's `inject:` semantics:

    use_factory(
        provide="CONNECTION",
        factory=lambda opts, log: DatabaseConnection(opts.get(), log),
        injects=[OptionsProvider, "LOGGER"],
        #           ^^^               ^^^^^^^
        #           class token       string token
    )

Wrap any entry in `OptionalDep` to soften the resolution:

    injects=[OptionsProvider, OptionalDep("LOGGER")]

Async factories work transparently — `lauren_di` awaits the return value
when it's a coroutine, so an `async def` factory is just a
factory.

<!-- docs-contract: run -->
```python
from lauren_di import DIContainer, use_factory

container = DIContainer()
container.register_custom(use_factory(provide="greeting", factory=lambda: "hi"))
```

### use_existing

```text
use_existing(*, provide: Any, existing: Any) -> CustomProvider
```

Alias `provide` to an already-registered `existing` token.

Both tokens resolve to the same instance under singleton scope.
Multiple aliases can chain through several `use_existing` rows
— `lauren_di` walks the chain at resolve time and rejects cycles loudly.
Aliases inherit the existing provider's scope.

Typical use case: expose the same logger under two names so
legacy code injecting `"AliasedLoggerService"` keeps working
while new code injects the class directly:

    use_existing(provide="AliasedLoggerService", existing=LoggerService)

<!-- docs-contract: run -->
```python
from lauren_di import DIContainer, injectable, use_existing


@injectable()
class Greeter:
    pass


container = DIContainer()
container.register(Greeter)
container.register_custom(use_existing(provide="greeter", existing=Greeter))
```

### ProviderOverride

```text
ProviderOverride(
    token: Any,
    kind: str,
    value: Any = None,
    values: tuple[Any, ...] = (),
    use_class: type | None = None,
    factory: Callable[..., Any] | None = None,
    injects: tuple[Any, ...] = (),
    existing: Any = None,
    scope: Scope | None = None,
    optional: bool = False,
    role: str = "provider",
)
```

Replacement for every registration of `token` in one app build.

`kind` selects the payload: `"value"` (`value`), `"values"`
(`values` — replaces a whole multi-binding set), `"class"`
(`use_class`), `"factory"` (`factory` + `injects`) or
`"existing"` (an alias to `existing`). `scope` is `None` when the
override should inherit the replaced provider's scope. An `optional`
override that never matches a registration is ignored instead of failing
the build.

<!-- docs-contract: run -->
```python
from lauren_di import ProviderOverride

override = ProviderOverride(token="clock", kind="value", value="frozen")
assert override.optional is False
```
